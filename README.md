# GermesControl

Desktop-приложение для АН «ГермесГарант»: контроль объектов недвижимости, договоров
и рекламных выгрузок между четырьмя источниками данных — сайтом компании, ILVO CRM,
Kufar и Bizlida.

Стек: **Electron + чистый JavaScript/HTML/CSS** (без React/Vue/Bootstrap/Tailwind,
без SQL-баз данных — данные хранятся в файлах JSON/XLSX/XML внутри `data/`).

## Запуск

Приложение — desktop-GUI на Electron, ему нужен настоящий дисплей, поэтому оно
**не запускается в браузерном превью Replit**. Проверяйте его на своей машине:

```bash
npm install
npm start
```

## Сборка portable-версии для Windows

Для создания переносимой 64-битной версии приложения выполните:

```bash
npm install
npm run build:portable
```

Готовый файл появится в `dist/` с расширением `.exe`. Конфигурация сборки
использует иконку `build/icon.ico`; установщик не требуется — exe можно
скопировать и запустить на другом Windows-компьютере.

## Источники данных

| Источник              | Формат | Способ загрузки          |
|------------------------|--------|---------------------------|
| Сайт ГермесГарант      | JSON   | автоматически из полного архива по URL (также доступен файл) |
| ILVO CRM               | XLSX   | вручную, файл             |
| Kufar                  | XML    | вручную (файл или ссылка) |
| Bizlida                | HTML / XLSX | прямое обновление по кнопке; XLSX — запасной способ |

Полный архив объектов сайта автоматически загружается по адресу
`https://germesgarant.by/data/objects-source.json` (актуальные объявления также
публикуются отдельно в `objects.json`). Это сохраняет в сверке снятые с продажи
объекты со статусом `sold`. ILVO загружается вручную из XLSX.
Kufar загружается вручную из XML или по настроенной ссылке на XML-фид.

### Bizlida

В панели **«Загрузить данные» → Bizlida → «Обновить Bizlida»** программа
обходит все страницы раздела `https://bizlida.by/baraholka/cat/37`, отбирает
объявления «АН ГермесГарант» и загружает полные карточки. Автор каждой карточки
проверяется по аккаунту агентства. Загружаются цена BYN, заголовок, полное
описание, доступные характеристики, ссылки на фото и даты. Номер договора
из описания используется только для сопоставления, не для проверки договоров.

Запросы выполняются последовательно с паузами; в панели отображается ход
загрузки страниц и карточек. Обновление может занять несколько минут, закрытие
панели его не прерывает. После успешной загрузки всего набора сохраняется
JSON-снимок в `data/uploads/bizlida/`, обновляется источник и **автоматически
запускается сверка**, независимо от настройки проверки после ручного импорта.
Дата в панели — время последней успешной загрузки.

При сетевой ошибке, блокировке, нераспознанной странице/карточке, нарушенной
пагинации или отсутствии объявлений обновление останавливается: частичный
результат не заменяет предыдущие данные и новая сверка не запускается.
Пустой набор намеренно требует ручного разбора, чтобы сбой сайта не удалил
все объявления. Изменение вёрстки Bizlida может потребовать обновления сборщика.
Если загрузка сохранена, но сверка не удалась, приложение сообщает об этом
отдельно; сверку можно запустить повторно. Сбор работает, пока открыто приложение.

Автоматическое обновление охватывает только указанный раздел, не другие
категории Bizlida. Защита сайта не обходится; перед регулярным использованием
проверьте действующие условия площадки.

Для ручного импорта выберите **«Загрузить данные» → Bizlida → «Из XLSX»**. Поддерживается
новая шестиколоночная выгрузка: ссылка, заголовок, цена **BYN**, краткое описание,
автор и полное описание; также поддерживаются прежние выгрузки с фото, ссылкой,
описанием и ценой (с заголовками или без них). Актуальная выгрузка содержит один
лист; дата и фото могут отсутствовать.

Номер договора извлекается из полного описания, когда он там указан, и используется
только как запасной ключ сопоставления, если адрес нельзя уверенно определить.
Он не участвует в проверках наличия/формы договора и не увеличивает счётчик
«Без договора» для Bizlida. Населённый пункт, улица, дом и корпус извлекаются из
доступного текста; адрес офиса из рекламной подписи не используется. Недостающие
сведения не выдумываются. Ссылка, описание, фото и исходная дата сохраняются,
если они есть в выгрузке.

Сверка включает четыре источника, все пары доступных полей, статистику и
XLSX-отчёты. Цены внешних площадок сравниваются только с ILVO. Для Bizlida
используются адрес, населённый пункт, заголовок и доступные характеристики:
одинаковой цены или улицы без дополнительных признаков недостаточно.
Для неполных адресов также учитываются площадь участка, год постройки,
этажность и другие явно указанные признаки. Площадь по СНБ сопоставляется
с площадью по СНБ, а не с общей площадью квартиры. «Дом» и «Дача» совместимы
для садовых объектов, но квартира и дом не объединяются.
Улица уточняется сведениями из описания; числовые названия улиц и разные
записи корпуса поддерживаются. Расстояние «от Лиды» не делает Лиду адресом.
При равнозначных кандидатах запись остаётся отдельной, а не объединяется
наугад. Если Bizlida ещё не загружена, наличие на ней не подтверждено —
загрузите актуальный файл перед проверкой.
Ранее импортированные объявления повторно разбираются из сохранённых
исходных текстов при загрузке приложения; старый отчёт пересчитывается.

Ожидаемый формат полей одинаков для всех источников: `id, title, type, dealType,
city, address, price, priceUsd, rooms, totalArea, livingArea, kitchenArea, floor,
floors, description, contractNumber, status`. В «Настройках» есть кнопка «Скачать
примеры файлов», которая генерирует образцы `.json/.xlsx/.xml` в этом формате.
Для JSON сайта статус `status.type = "sold"` и `status.date` означают, что объект
снят с продажи: его отсутствие на других площадках не считается ошибкой, а дата
показывается в реестре объектов.

## Структура проекта

```
main.js                 — точка входа Electron (главный процесс)
preload.js               — contextBridge API для рендерера
src/main/                — бизнес-логика главного процесса
  schema.js               общая схема объекта, типы ошибок
  sampleData.js           генератор демо-набора данных (первый запуск)
  parsers.js              разбор XLSX / JSON / XML источников
  compare.js              сравнение источников, поиск ошибок и статистики
  reports.js              генерация XLSX-отчётов с расширенными колонками,
                          сводкой и цветными диаграммами
  dataStore.js            файловое хранилище (data/) + electron-store для настроек
  ipcHandlers.js          IPC-обработчики между рендерером и главным процессом
render/                  — интерфейс (vanilla JS, ES-модули, без сборщика)
  index.html, css/, js/views, js/components
data/                     — рабочие данные приложения (создаётся при первом запуске);
                           в uploads хранится не более 5 последних файлов каждого источника
```

## Демо-данные

При первом запуске приложение автоматически создаёт демонстрационный набор данных
(с намеренными расхождениями и отсутствующими объектами), чтобы Dashboard и все
разделы сразу были содержательными.
