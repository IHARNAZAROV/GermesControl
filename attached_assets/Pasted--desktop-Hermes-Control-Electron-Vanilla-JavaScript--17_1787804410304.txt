Создай desktop-приложение **Hermes Control** на **Electron + Vanilla JavaScript** для АН «ГермесГарант».

## Главная задача

Приложение предназначено для контроля объектов недвижимости, договоров и рекламных выгрузок.

В системе используются три основных источника данных:

1. **ILVO CRM** — данные объектов выгружаются вручную в формате XLSX.
2. **Kufar** — объявления автоматически передаются из ILVO через XML:
   `https://ilvo.pro/posting/Ea59071BdDe82DC8B2aCFBaa88AB80cf.xml`
3. **Сайт ГермесГарант** — объекты выгружаются вручную в формате JSON.

Приложение должно в дальнейшем сравнивать данные между этими источниками, находить отсутствующие объекты и выявлять несоответствия.

---

# 1. Технологии

Использовать:

* Electron
* Vanilla JavaScript
* HTML5
* CSS3
* Node.js
* Electron IPC
* `xlsx` для XLSX
* `fast-xml-parser` для XML
* `fs-extra` для работы с файлами
* `dayjs` для дат
* `electron-store` для настроек приложения

**НЕ использовать:**

* SQLite
* любую другую SQL-базу данных
* React
* Vue
* Angular
* Svelte
* Electron Forge
* Electron React Boilerplate
* Bootstrap
* Tailwind CSS

Интерфейс должен быть реализован на чистом HTML/CSS/JavaScript.

# 2. Хранение данных

Не использовать SQLite.

На первом этапе использовать файловое хранение:

```text

XLSX
XML
```

Настройки приложения хранить через `electron-store`.

Исходные загруженные файлы не изменять.

Приложение должно хранить информацию о последних загрузках и результатах проверок локально.

# 21. Важное требование

Не создавать сейчас реальную интеграцию с ILVO или Kufar API.

XML должен пока загружаться вручную по ссылке/через файл.

XLSX ILVO — вручную.

JSON сайта — вручную.

Архитектура должна быть подготовлена для последующего автоматического получения данных, но сейчас достаточно ручного импорта.

# 22. UX-принцип

Главная страница должна отвечать только на три вопроса:

### 1. Сколько у нас объектов?

### 2. Всё ли совпадает между системами?

### 3. Какие проблемы требуют внимания?

Не превращать Dashboard в огромную таблицу.

Подробная информация должна находиться в:

```text
Объекты
Договоры
Сравнение площадок
Ошибки
Аналитика
Отчёты
```

Главная страница — **сводка состояния системы**, а не место для просмотра всех данных.

Создай интерфейс именно в соответствии с этим принципом.
